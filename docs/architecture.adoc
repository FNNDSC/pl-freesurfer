= pl-freesurfer: architecture
:toc:

== Abstract

pl-freesurfer is a spec, an image and a workflow. `freesurfer/freesurfer.py` holds the `PluginSpec` and the default template; `freesurfer/__main__.py` is three lines, `plugin_build(SPEC)` and the parser and main it returns; `freesurfer/models.py` re-exports shexec's records. The Dockerfile starts from FreeSurfer's own image, adds Python and the package, and sets the licence path. The workflow tests on the host, frees the runner's disk, builds and pushes the image, and uploads the plugin's description on a tag.

== The spec

`SPEC` names the plugin `freesurfer`, gives it the version `1.0.0 (FreeSurfer 8.2.0)`, so that `--version` prints both while the package's own version, read by `chris_plugin_info` from its metadata, stays `1.0.0`; the title `FreeSurfer 8.2.0 recon-all over every subject`, which the plugin list and the pipeline editor show; the category `Neuroimaging`; `32Gi` of memory and two cores, because FreeSurfer 8's `recon-all` runs SynthSeg and SynthStrip by default, `mri_synthseg` alone peaked at 15.7 GB in the smoke on FreeSurfer's sample volume, and FreeSurfer's own guidance for the 8 series is 24 to 32 GB per run, where pl-fshack on FreeSurfer 7 asked `16Gi`; `--threads` multiplies this, since each worker is a whole `recon-all` in the same container; and the defaults `exec`, `analyzeFileIndex` and `fileFilter`. The default template is `recon-all -all -i %{inputWorkingDir}/%{inputWorkingFile} -s %{inputWorkingDir|basename} -sd %{outputWorkingDir}`: the input is the chosen file in the subject's input directory, the subject's name is the directory's name, and the subjects directory is the directory's counterpart in the output tree, which pfdo_run has already created, so `recon-all` creates the subject directory inside it and never meets an existing one. `analyzeFileIndex` is `f`, one run per directory on its first file, which is how a DICOM series is given to `recon-all`; `fileFilter` is empty, since the file to choose depends on what the previous plugin left, and the user narrows it when a directory is mixed. The manual's words are the spec's remaining fields, over the sections every plugin on the stack shares.

== The package

`__main__` calls `plugin_build(SPEC)` and binds `parser` and `main`; the console script `freesurfer = "freesurfer.__main__:main"` is what the image's command and ChRIS run. `models` re-exports shexec's records so a test or a tool imports from `freesurfer.models` and nothing below. `pyproject.toml` names `chris_plugin` and `shexec` as dependencies, the first directly because `chris_plugin_info` looks for the plugin among the distributions that depend on chris_plugin itself; `setup.cfg` carries the author and URL that the tool reads from legacy metadata. There is no `plugin_run`, no engine class and no parser of the plugin's own.

== The image

The Dockerfile starts from `freesurfer/freesurfer:8.2.0`, FreeSurfer's own image, which carries `FREESURFER_HOME` and `PATH` set for its programs and its own Python under `fspython` for its own use. The plugin needs a system Python of 3.11 or later, which the image's base, Rocky Linux 8 with a 3.6 `python3`, does not carry, so Python 3.12 is installed from the distribution's AppStream packages, the package is installed into it with pip, and the console script lands in `/usr/local/bin`. The base also carries a bash script named `freesurfer` in `$FREESURFER_HOME/bin`, which prints a welcome banner and is first on the base's `PATH`; left alone it shadows the console script, and `chris_plugin_info` records its directory as the plugin's `selfpath`, so the Dockerfile puts `/usr/local/bin` ahead of it and the command `freesurfer` is the plugin's. FreeSurfer's own `python3` and `fspython` are untouched; the plugin's package is not visible to them. The licence file is copied to `$FREESURFER_HOME/license.txt` and named by `FS_LICENSE`, which FreeSurfer 7 and later read; a site mounts its own file over that path. Labels record the plugin's version and the FreeSurfer version. The image's command is `freesurfer --man /tmp /tmp`.

== The workflow

The test job runs on the host on 3.11 through 3.14, with a stand-in `recon-all` on `PATH` that records its arguments and creates the subject directory, so the tests need no FreeSurfer and run in a second. The build job frees the runner's disk first, removing the preinstalled toolchains with `jlumbroso/free-disk-space`, because the FreeSurfer base image is fourteen gigabytes compressed and pl-fshack's releases had to be built by hand for that reason; it then builds the image, runs `freesurfer --version` and `chris_plugin_info` inside it, pushes to Docker Hub and ghcr.io, and on a tag checks that the tag matches `__version__` and uploads the plugin's description to cube.chrisproject.org. The organisation's Docker Hub and CUBE secrets are what the upload uses.

== Verification

Six tests. The spec names FreeSurfer in its title and version and carries the template as the default. A run with no flags over two subject directories, each with a DICOM and a note, runs the stand-in `recon-all` once per subject on the DICOM, names each subject after its directory, leaves the subject directory and a `jobs.jsonl` line per subject, and writes the plugin's span with its name. A stand-in that exits 1 for every subject fails the run with 1. The parser serialises for ChRIS with the template as `exec`'s default. `--man` names `recon-all` and the FreeSurfer version and `--version` prints both versions. `chris_plugin_info` describes the installed package with its type, entry point, version, title, documentation and memory limit. Ruff is clean with the stack's rule set.
